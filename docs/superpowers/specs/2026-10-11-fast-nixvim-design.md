# Fast Nixvim Config: Design

Date: 2026-10-11

## Goal

A fully functional personal Neovim configuration, built as a nixvim flake, optimized for startup time and in-editor latency. Structured as reusable modules so it can be published later.

## Decisions

### Plugin policy
- Use existing Rust-backed plugins only. No custom plugins and no nvim-oxi.
- Rust-backed plugins in scope: blink.cmp (completion), fff.nvim (fuzzy find and grep), blink.pairs (autopairs).
- For every other feature, apply this rule in order:
  1. Use a Neovim built-in if it covers the need (LSP client, `vim.diagnostic`, built-in explorer).
  2. Otherwise use the fastest mature Lua plugin, lazy-loaded.
- Rust external tools (ruff, stylua, rg, fd) are used behind the editor where relevant.
- Glue is Lua generated by nixvim from Nix; no hand-written Lua layer beyond what nixvim emits.

### Feature scope
LSP, completion, fuzzy find/grep, treesitter highlighting, git signs and diff, file explorer, statusline, formatting and linting, DAP, diagnostics UI.

Out of scope: AI integration, notes.

### Languages
- Full wiring (LSP, format, lint, DAP where applicable): Rust, Nix, Go, Python, shell.
- All other languages: treesitter highlighting only.

### Speed
- Target: under 20 ms startup. This is a target, not a gate; a feature landing at slightly above it does not block.
- In-editor latency (completion, picking on large repos) is also a design goal.
- Measurement: `nix run .#bench` reports startup time and the slowest plugins, on demand. No hard CI budget (noisy in the Nix sandbox).

### Packaging
- Base: nixpkgs 25.11 via `nixvim` branch `nixos-25.11`.
- blink-cmp comes from nixpkgs unstable (the 25.11 pin is stale). fff-nvim uses unstable's recipe and `zig`, built on the stable toolchain: its prebuilt lib links the unstable glibc, which the 25.11 Neovim cannot load. blink-pairs is the stable 0.4.1: unstable's 0.7.1 needs Neovim 0.12+.
- The unstable package set is the module option `nvimRust.unstable` (default `pkgs`); the flake's `nixvimModules.default` sets it to its `nixpkgs-unstable` input with `mkDefault`.
- Flake outputs: `packages.default` and `nixvimModules.default`. No NixOS or home-manager wrapper modules.

### Look and keys
- Leader: space.
- Colorscheme: tokyonight (night), replacing the scaffold's gruvbox.
- Keymap hints: mini.clue.

## Known risks
- Few Rust-backed plugins exist. Treesitter, explorer, git, statusline, and format/lint are all Lua, so "all plugins in Rust" resolves in practice to the fallback rule above.
- Mixing stable and unstable plugins can cause ABI or Lua API mismatches between a plugin and the 25.11 Neovim (0.11.x). Needs verification when wiring each unstable plugin.
- Rust plugins build from source in Nix (`rustPlatform.buildRustPackage`), so first builds are slow without a binary cache hit.

## Current state
Scaffold exists: `flake.nix` (nixvim `nixos-25.11`, `packages.default`, `checks.default`) and `config/default.nix` (basic options, gruvbox). `nix flake check` passes on x86_64-linux.

## Out of this spec
Module layout, concrete plugin choices per Lua feature (explorer, git, statusline, formatter, linter, DAP), and lazy-loading triggers are decided in the implementation plan.
